# Анализ устойчивости метрик к геометрическим искажениям

## 0. Берём патчи H&E из нашего датасета.

## 1. Фиксируем нормализацию и grayscale шаги предобработки (остальные мы не используем пока).

В случае LPIPS/DISTS можно рассмотреть вариант с RGB изображением.

## 2. Для каждого патча сохраняем базовое значение метрики на паре (оригинал, оригинал).

Для сравнения (к примеру, для MI будет не вырожденное распределение (const +- eps), а энтропия - H(I_0).
Обозначим H&E патч как I_0. Базовое значение метрики на идентичной паре: M_0= metric(I_0, I_0)

## 3. Для каждого уровня shift, rotate, magnitude (и их комбинаций) прогоняем наш набор изображений. Всегда одна интерполяция (interpolate=INTER_LINEAR), один ресемплинг (border=REFLECT_101), затем кроп ~12 px по краю (чтобы края не влияли на метрику). Желательно для каждого уровня искажений прогонять их с 5–10 разных seed и усреднять M_k для стабильности (пока необязательно).

Таким образом после применения к I_0 набора трансформаций разной силы получаем: I_1, I_2, ... это версии того же изображения, искажённые с различными уровнями параметров (shift, rotate, magnitude).
Считаем метрику для всех условий (M_k = metric(I_0, I_k)) → получаем распределения по уровням. 

Линейная (ShiftScaleRotate) — сначала варьируем по отдельности
    - shift_limit: 0.005, 0.01, 0.02, 0.04 (≈ 1.3 / 2.6 / 5.1 / 10.2 px)
    - rotate_limit: 2, 4, 8, 12 градусов
    - scale_limit: 0 (думаю не стоит пока добавлять его)

Нелинейная (GridElasticDeform)
    - num_grid_xy: (5, 5) [потом можно попробовать другие попробовать]
    - magnitude: 1, 3, 6, 9, 12 (5 уровня силы)

Порядок прогонов: сначала чистые лестницы по одному параметру (остальные = 0), затем комбинации.

## 4. Как оцениваем реакции метрики

По каждому уровню k: Медиана M_k + IQR.

Графики:
    - Линия median Y - M_k с лентой IQR, X - уровень искажения.
    - KDE/violin распределений M_k по уровням (дополнительно).

# Численные индексы описывающие поведение метрик на разных уровнях геометрических искажений.

## 1. Что именно мы хотим зафиксировать

Три феномена поведения метрик:

1. **Резкий “обрыв” при первом уровне искажений**
   (M_0 \to M_{k_1}): большой скачок ∆ при очень малом shift (0.005).

2. **Насыщение в конце — малое изменение на последних уровнях искажения**
   (M_{k_max-1} \to M_{k_max}): ∆ при больших shift ~ 0.

3. **Отсутствие “плато устойчивости”**
   Нет диапазона малых сдвигов, где метрика была бы почти неизменной.

Задача — **сделать это “видимым в цифрах”**, а не только на графике.

## 2. Простая численная декомпозиция: первый шаг vs остальные

Предлагаю для каждой метрики и вида искажения считать:

### 2.1. Early Saturation Score (ES)

Для shift возьмём уровни (s_0 = 0), (s_1 = 0.005), (s_2 = 0.01), …

Пусть:

* (M_0) — медиана по всем патчам при отсутствии искажения,
* (M_1) — медиана при уровне (s_1),
* (M_max) — медиана при максимальном уровне (например, 0.04).

смотрим на накопленное падение к шагу k:

[Drop_{k} = M_k - M_0, Drop_{total} = M_max - M_0]

[ES_{k} = \frac{Drop_{k}}{Drop_{total}}]

Интерпретация:
* **Drop_k** — насколько сильно метрика просела уже на k-ом уровне.
* **Drop_total** — общий провал между “идеальным” и “максимальным” искажением.
* **ES_k** — доля “падения”, которая происходит уже на k-ом шаге.

* Идеал: ES_1,2 < 0.3 (метрика потратила менее 25% своего диапазона на малые сдвиги, оставив 75% на различение серьезных проблем).
* SSIM: Скорее всего ES_2 ~ 0.8 (насыщение, "паника" раньше времени) → метрика **очень “неробастна”** к малейшему misalignment.

## 3. Изменение наклона (производной), то есть насыщение (saturation).

### 3.1. Late Sensitivity Ratio (LSR)

Этот индекс сравнивает скорость изменения метрики на последнем шаге со средней скоростью изменения.
Идея:
    - Если метрика линейна, она растет на последнем шаге так же бодро, как и в среднем (LSR≈1).
    - Если метрика насытилась (вышла на плато), она почти не меняется на последнем шаге (LSR→0).

[Slope_{last} = \frac{|M_{max}-M_{prev}|}{Level_{max}-Level_{prev}}]
[Slope_{global} = \frac{|M_{max}-M_0|}{Level_{max}}]

[LSR_last = \frac{Slope_{last}}{Slope_{globak}}]
    - **Slope_global (Глобальная скорость):** Это средняя крутизна линии от точки $(0, 0)$ до $(MaxLevel, MaxValue)$. Она усредняет и "медленное" начало, и "быстрый" конец.
    - **Slope_local (Локальная скорость):** Это крутизна метрики только на последнем участке.

### 3.2 Почему LSR > 1?

Вспомним формулу: [LSR = \frac{Slope_{local}}{Slope_{global}}]

Значения LSR рассказывают историю о форме кривой:

*   **LSR < 1 (например, 0.1):** **Насыщение (Saturation).** График выгибается горбом (как SSIM). Метрика быстро выросла в начале и "устала" в конце. Скорость в конце ниже средней.
*   **LSR ≈ 1:** **Чистая Линейность.** Метрика растет с постоянной скоростью от самого начала до конца.
*   **LSR > 1 (например, 1.2 – 1.5):** **Ускорение (Acceleration).** Метрика в начале прощает ошибки (низкий старт), но на больших искажениях становится очень строгой и чувствительной.

### 3. Почему это хорошо?

Для задачи гистологии (Registration / QC) сценарий **LSR > 1** (в разумных пределах, скажем, до 1.5–2.0) — это **идеальный профиль**:
*   Метрика игнорирует шум (сдвиг < 1px).
*   Метрика жестко наказывает реальные ошибки (сдвиг > 5px).

Это именно то поведение, которое показывает: "устойчивость к малым искажениям + чувствительность к большим".
